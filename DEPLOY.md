# Первый запуск бота с ручной выдачей курсов

Эта инструкция включает платный хостинг. Сейчас ничего не оплачено и не развёрнуто автоматически. Сначала можно опубликовать английский интерфейс на прежнем GitHub Pages; это останется открытой версией без платных ограничений.

## Что подготовлено

Ученик открывает приложение через Telegram. Бесплатно доступны уроки 1–3 учебника. Остальные материалы сервер выдаёт только после проверки Telegram-аккаунта и разрешений в базе. Владелец управляет доступом из личного чата с ботом.

Пакеты:

| Ключ | Материалы |
| --- | --- |
| `book8` | Учебник 1–8 |
| `book16` | Учебник 1–16 |
| `hsk1` | HSK 1 плюс пробные уроки учебника |
| `hsk2` | HSK 1 и HSK 2 плюс пробные уроки учебника |
| `all` | Все курсы |

Для каждого пакета есть срок 30 дней или бессрочно. Прямое закрытие пакета и блокировка всего аккаунта действуют независимо. Если у ученика остаётся другой пакет, который включает те же материалы, они остаются доступны. Например, отзыв `hsk1` не отменяет доступ, предоставленный пакетом `hsk2` или `all`. Разблокировка аккаунта восстанавливает его неистёкшие пакеты.

## 1. Подготовьте бота

В `@BotFather` откройте своего бота и получите его токен. Не отправляйте токен в чат с ассистентом, не добавляйте в GitHub и не вставляйте в HTML. Он понадобится только в секретных настройках хостинга.

Если бот уже обслуживается другим сервисом, не подключайте второй обработчик одновременно: сначала выясните, какие функции выполняет прежний сервис. Этот проект использует один процесс `getUpdates`; он не удаляет существующий webhook и не отключает чужой сервис автоматически. При конфликте polling не сможет работать, а доступ останется закрытым по умолчанию.

## 2. Создайте сервер на Render

Можно использовать любой хостинг Python с HTTPS и постоянным диском. Ниже один конкретный вариант.

1. Войдите на https://dashboard.render.com и подключите GitHub.
2. Выберите **New → Blueprint** и репозиторий `filipp-osmanov-star/Hanzi-`, ветку `main` после слияния PR.
3. Render прочитает `render.yaml`. Посмотрите стоимость перед подтверждением: файл предлагает платный Web Service `starter` и постоянный диск 1 GB. На бесплатный временный диск базу покупателей размещать нельзя — она исчезнет при перезапуске или обновлении.
4. Введите секрет **BOT_TOKEN**. В **BOT_USERNAME** укажите имя бота без `@`. **ADMIN_IDS** пока можно оставить пустым: до настройки никто не получит административные права.
5. Создайте сервис и дождитесь состояния **Live**. Render сам задаёт `RENDER_EXTERNAL_URL`, поэтому `APP_URL` там можно не вводить. Вы получите адрес вида `https://имя-сервиса.onrender.com`.

При ручном создании Web Service используйте:

- Build command: `pip install -r requirements.txt`
- Start command: `gunicorn --workers 1 --threads 8 --timeout 60 --bind 0.0.0.0:$PORT 'server:create_app()'`
- Health check: `/healthz`
- Persistent disk mount path: `/var/data`
- `ACCESS_DB=/var/data/access.sqlite3`
- Все остальные переменные из `.env.example`.

**Один worker и одна реплика обязательны для polling.** Восемь HTTP-потоков обслуживают приложение внутри этого worker. Не включайте `--preload` и автоматическое горизонтальное масштабирование. Для нескольких экземпляров понадобится отдельный процесс бота и общее хранилище.

## 3. Назначьте себя владельцем

1. Откройте своего бота в Telegram и отправьте `/id`.
2. Бот вернёт ваш числовой Telegram ID.
3. На Render откройте **Environment → ADMIN_IDS**, вставьте этот ID и сохраните с перезапуском сервиса.
4. Отправьте боту `/admin`. Должны появиться кнопки **Заявки** и **Ученики**.

`ADMIN_IDS` задаётся только на сервере. Первый посетитель, поле `username`, значение в браузере или параметр ссылки не могут назначить администратора. Несколько владельцев задаются числовыми ID через запятую.

## 4. Переключите адрес мини-приложения

В `@BotFather`: `/mybots` → ваш бот → **Bot Settings → Menu Button → Configure Menu Button**. Замените URL на новый HTTPS-адрес Render. Если вы настраивали отдельную Main Mini App, обновите её URL тоже. В интерфейсе BotFather названия пунктов могут меняться; смысл — сменить адрес запуска приложения.

Команда `/start` в самом боте также показывает кнопку с новым адресом.

Прежняя ссылка GitHub Pages остаётся публичной. Не продавайте ограниченный доступ по ней: `index.html` там по-прежнему содержит всю открытую базу. На коммерческом домене запускайте именно `server:create_app()`, а не статическую раздачу файлов репозитория. По прямому адресу сервер показывает только пробный курс; защищённые JSON, исходники и база не раздаются HTTP-сервером.

Материалы, уже опубликованные на GitHub, нельзя сделать секретными задним числом. Новая проверка контролирует выдачу с нового сервера, а не копии прежней открытой версии. Закрытие доступа также не может стереть материал, который ученик уже успел получить или скопировать.

## 5. Как выдавать доступ с телефона

1. Ученик открывает бота и приложение.
2. В приложении выбирает **Доступ → пакет → Запросить доступ**. Либо отправляет боту `/request`.
3. Вы открываете `/admin → Заявки`, выбираете ученика.
4. После подтверждённой оплаты нажимаете **Открыть: нужный пакет**, затем **На 30 дней** или **Бессрочно**.
5. Ученик нажимает **Обновить доступ**. Приложение также перепроверяет разрешения раз в минуту и при возврате на экран.

Для отзыва: `/admin → Ученики → ученик → Закрыть: пакет`. Для общей блокировки: **Блокировать все курсы**. Найти ученика напрямую можно командой `/user ЧИСЛОВОЙ_ID`. Изменения фиксируются в журнале базы.

Блокировка применяется к авторизованному Telegram-аккаунту. Публичные пробные уроки без входа и другие аккаунты человека она не блокирует. Уже загруженную страницу нельзя гарантированно отозвать без связи с сервером; следующая проверка, обновление или открытие страницы применят новые права.

## Оплата

**Автоматической оплаты и проверки переводов в этой версии нет.** Здесь подготовлена ручная выдача и отзыв курсов. Суммы, счета и платежи не создаются. Выдавайте доступ после реального подтверждения покупки, а не скриншота от ученика.

Для продажи цифрового доступа через Telegram нужны Telegram Stars. До начала продаж следует отдельно подключить выставление счетов, обработку `successful_payment`, возвраты и `/paysupport`, а также согласовать условия и права на коммерческое использование материалов. Нынешние `/support`, `/paysupport` и `/terms` показывают текст `SUPPORT_TEXT`; по умолчанию это контакт с владельцем, а не полноценная оферта или платежная поддержка.

## Резервные копии и обновления

- База `access.sqlite3`, включая журнал и заявки, находится на постоянном диске. Используйте снимки диска хостинга либо согласованную SQLite backup-копию. Не копируйте только основной файл во время записи, игнорируя WAL.
- Не размещайте базу, токен, `.env` или дампы пользователей в GitHub. Они включены в `.gitignore`.
- Прогресс обучения пока хранится в браузере, отдельно от прав доступа. Перед переходом на новый домен ученик открывает **Инфо → Экспорт прогресса**, а на новом — **Импорт прогресса**. Перенос не происходит автоматически между доменами.
- Отзыв курса не удаляет локальные отметки ученика. При повторном открытии курса они сохраняются.

## Проверка перед использованием

С двух разных Telegram-аккаунтов проверьте: пробные уроки, заявку, выдачу ровно одного курса, пересылку общей ссылки, отзыв и блокировку. Перезапустите сервер и убедитесь, что права сохранились. Пользователю с чужим аккаунтом должны быть видны только его собственные разрешения. После этого отдельно тестируйте Stars, когда платежная интеграция будет добавлена.
